# 验收与测试计划

## 1. 测试目标

- 验证登录、建档、记录、汇总、仪表盘主路径稳定。
- 验证 Next 功能开发时不会破坏 Current 行为。
- 为产品、研发、测试提供一致的验收清单。
- 验证 Redis 缓存提升性能时不破坏数据一致性、权限隔离和故障降级。
- 验证所有新增功能都能在 `zh-Hans`、`zh-Hant`、`en`、`ja`、`ko` 下正常显示或有明确翻译兜底。

## 2. Current 后端 e2e 场景

当前 `apps/backend/test/app.e2e-spec.ts` 已覆盖：

- 登录并返回用户、access token、refresh token。
- 未建档用户获取 `/health/profiles/me` 返回 404。
- 当前用户建档成功。
- 饮食记录写入成功。
- 运动记录写入成功。
- 鉴权查询饮食历史成功。
- 鉴权查询运动历史成功。
- 未鉴权查询历史返回 401。
- 获取日汇总成功。
- 获取今日仪表盘成功。

## 3. MVP 验收

### 登录与建档

- 正确手机号和验证码可以登录。
- 未建档进入建档页。
- 已建档进入首页。
- 非法档案字段不能提交。

### 饮食记录

- 支持四类餐次：breakfast、lunch、dinner、snack。
- 营养字段必须为非负数。
- 写入后日汇总热量和营养更新。

### 运动记录

- 支持 aerobic、strength、flexibility。
- 时长必须大于 0。
- 写入后日汇总运动消耗更新。

### 仪表盘

- 展示健康分、档案摘要、卡片指标、AI 洞察、日汇总。
- 无记录时仍能返回默认汇总。
- 刷新失败时显示重试。

### Redis 缓存

- `daily-summary` 和 `dashboard/today` 首次访问可从数据库聚合，后续相同用户和日期命中缓存。
- 新增饮食或运动记录后，对应日期日汇总和首页缓存失效，再次读取能看到新数据。
- Redis 不可用时，登录、建档、记录写入、日汇总、仪表盘仍可走数据库路径返回业务结果。
- 缓存 key 包含用户作用域，不同用户不能读到彼此缓存。
- 不缓存 refresh token 明文、Garmin token、验证码明文、报告文件本体。

## 4. Next 功能验收

### 数据趋势

- 周/月/年切换正确。
- 无数据显示空态。
- 指标异常显示文字标签。
- 趋势接口返回空 points 时页面不崩溃。
- 趋势聚合缓存命中后响应结构不变。
- 指标事件、Garmin backfill 或手动记录写入后，受影响周期趋势缓存失效。

### AI 建议

- 建议包含类型、标题、原因、动作。
- 采纳、稍后、忽略状态可更新。
- AI 文案不输出诊断、处方或急救判断。
- 建议动作更新后，刷新列表不能再次显示旧的 pending 状态。
- Redis 不可用时，建议列表可降级为数据库 / 规则引擎实时生成。

### 我的页

- 档案入口可达。
- 报告、目标、通知、隐私、安全入口可达。
- 退出登录后回到登录页。
- 语言与单位设置入口可达，切换后页面文案即时刷新。

### 健康档案扩展

- 健康档案页展示完整度、缺失项、基础信息、健康背景和数据来源。
- 未填写慢病史、过敏史时展示“未填写”，不展示“正常”或“无异常”。
- 用药管理可新增药品计划，并能执行已服用、稍后、跳过动作。
- 停用药品后不再进入今日待服提醒，但历史记录保留。
- 体检报告可展示最新报告、关键指标和历史报告。
- 体检报告异常项必须有文字标签，不只依赖颜色。
- 用药管理不输出处方或剂量建议，体检报告不输出诊断结论。
- 健康档案、用药、体检报告变化后，`profile-center` 缓存失效。

### 国际化

- 中文简体、中文繁体、英文、日文、韩文可切换。
- 跟随系统语言开启时，客户端会自动采用系统 locale。
- 手动切换后重启 App 仍保留语言偏好。
- 未支持语言回退到中文简体。
- API 请求带正确 locale，生成类内容和缓存按 locale 隔离。
- 长文案不会导致按钮、卡片、导航或设置页布局错位。
- 新增页面、弹窗、错误码和通知文案必须有多语言资源，不允许只在中文下可用。

### Garmin 设备接入

- 未连接时展示 Garmin 授权入口和同步指标说明。
- OAuth state 校验失败时不能创建设备连接。
- 授权成功后展示 `connected` 状态和最近同步时间。
- backfill 成功后标准化指标写入趋势数据源。
- webhook 重复推送不会产生重复指标事件。
- token 失效且刷新失败时标记为 `reauth_required`。
- 断开连接后停止同步，客户端不再展示为已连接。
- OAuth state 存在、过期、重复使用三类场景都有测试。
- backfill 并发触发时 Redis 同步锁只能允许一个任务执行。
- webhook 去重 key 命中时不重复写入 `health_metric_events`。
- 设备连接状态缓存会在授权、断开、同步失败、同步成功后失效。

### 报告

- 可按周/月生成报告摘要。
- PDF 导出失败时给出可重试状态。
- 分享前必须展示授权对象和数据范围。

## 5. 安全与权限

- 用户不能读取他人档案、记录、报告。
- 家庭共享必须校验授权范围。
- refresh token 失效后不能继续刷新。
- 退出登录后本地 token 清除。
- Redis 缓存不得绕过鉴权：未授权请求不能因为缓存存在而返回用户数据。
- Redis 中不得出现 Garmin token、refresh token 明文或其它长期敏感凭据。

## 6. 回归清单

- `npm run backend:build`
- `npm run backend:test`
- 移动端手动验证：登录 -> 建档 -> 首页 -> 数据 -> AI 建议 -> 我的
- 文档链接检查：`docs/README.md` 中所有相对链接可打开
- Redis 回归：缓存命中、写入失效、Redis 停止服务降级、跨用户隔离、Garmin 锁和去重
