# UI / UX 设计

本文档从当前产品方案中提炼移动端界面设计要点，并与现有 Flutter 主流程保持一致，供后续页面扩展与视觉设计使用。

## 1. 设计目标

产品需要兼顾：

- 健康数据查看的清晰度
- 记录操作的低门槛
- 中老年用户的可读性
- 后续智能分析能力的可展示性

核心体验目标：让用户从登录、建档到查看健康仪表盘的主路径尽量顺滑。

## 2. 当前已实现页面流

当前 `apps/mobile/lib/main.dart` 已实现三段式流程：

1. 登录页 `LoginView`
2. 建档页 `OnboardingView`
3. 仪表盘页 `DashboardViewWidget`

因此 UI 设计应优先围绕这三类页面深化，而不是一次铺开所有模块。

## 3. 设计原则

- 简洁：减少一次性展示的信息密度
- 明确：关键指标优先展示
- 友好：按钮足够大，表单步骤清晰
- 一致：统一色彩、圆角、卡片层级与按钮行为
- 可扩展：后续可承载更多记录类型与 AI 卡片

推荐视觉基调：

- 主色：蓝绿系
- 风格：清爽、可信、轻医疗感
- 组件：卡片式布局 + 大按钮 + 清晰分区

## 4. 关键页面设计

### 4.1 登录页

目标：

- 快速进入系统
- 降低首次使用门槛

建议结构：

```text
[Logo / 应用名]
[欢迎语]
[手机号输入框]
[验证码输入框]
[登录并继续按钮]
```

设计要点：

- 输入框标签要明确
- 按钮宽度尽量占满主要内容区
- 错误反馈直接出现在当前页

当前代码位置：`apps/mobile/lib/main.dart`

### 4.2 建档页

目标：

- 让用户一次完成基础信息录入
- 为仪表盘与建议系统提供基本数据

建议字段：

- 昵称
- 年龄
- 性别
- 身高
- 体重
- 目标

建议交互：

- 分组显示基础信息与目标信息
- 使用下拉选择性别与目标
- 提交按钮固定在底部主要区域

后续可增强：

- BMI 实时计算
- 分步骤 onboarding
- 引导文案说明目标差异

### 4.3 仪表盘页

目标：

- 第一时间传达“今天健康状态如何”
- 在一屏内展示核心指标与建议

建议布局：

```text
[顶部：用户称呼 + 健康分数]
[四宫格：步数 / 睡眠 / 饮水 / 热量]
[AI 洞察卡片]
[今日营养与运动摘要]
[快捷记录入口]
```

当前后端已提供：

- `healthScore`
- `cards`
- `aiInsights`
- `summary`

因此前端设计上应直接围绕这些数据结构布局，避免重复建模。

## 5. 建议的页面演进顺序

### Phase 1：围绕当前已实现主路径完善 UI

优先完善：

- 登录页视觉层级
- 建档页表单体验
- 仪表盘信息排版
- 统一错误态、加载态、重试态

### Phase 2：扩展记录能力

新增页面：

- 饮食记录页
- 运动记录页
- 日汇总详情页
- 周报 / 月报页

### Phase 3：增强平台能力

新增页面：

- 家人共享页
- 设备接入页
- AI 深度分析页
- 我的设置页

## 6. 可用组件建议

随着页面变复杂，建议逐步拆分组件：

- `DashboardScoreCard`
- `MetricGrid`
- `InsightCarousel`
- `NutritionSummaryCard`
- `ExerciseSummaryCard`
- `PrimaryActionButton`

当前阶段不必过度抽象，但可以在仪表盘稳定后开始沉淀复用组件。

## 7. 可访问性建议

针对健康类应用，建议从早期就注意：

- 字号不宜过小
- 颜色对比度足够明显
- 关键信息不要只靠颜色表达
- 按钮触控区域足够大
- 表单错误提示文字清楚直接

## 8. 与当前代码的对应关系

- 应用入口与页面流：`apps/mobile/lib/main.dart`
- 后端仪表盘数据来源：`apps/backend/src/health/health.service.ts`
- 仪表盘接口入口：`apps/backend/src/health/health.controller.ts`
